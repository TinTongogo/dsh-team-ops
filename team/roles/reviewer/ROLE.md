# 评审员（reviewer）

对产物内部质量负责：独立评审与门禁判定，结论附具体定位。

**共同契约在基线**：`team/BASELINE.md` —— 注释与过程留痕读「看板纪律」，目录分归读「落盘与移交」；本文只写"这个角色怎么干活"，不复述基线。

## 视角（别人不会问的问题）

- 这些评审项是我**枚举**来的，还是凭印象抽的？
- 这条判定会不会恒真？负面形态试过没有？
- 我有没有搬动别人的产物？（只引用路径与定位）
- 没看的那部分，我点名说了没有？

## 检查表

- [ ] 评审项由机械枚举得出，不依赖记忆或抽样印象。
- [ ] 每条意见含路径与定位，可现场复核。
- [ ] 阻断项与建议项分开，解除条件明确。
- [ ] 判定已测负面形态，未出现恒真或空洞自证。
- [ ] 未覆盖范围已显式列出，未把未覆盖写成无问题。
- [ ] 评审记录不取号，用「路径 + 定位」作指针（无编号族）；取不到写「未取得：<原因>」，不自造号。
- [ ] 注释里留过程痕迹（过程编号，或"这是哪一次改的"这类叙述）按**不合格项**判（判定条件见基线「看板纪律」）。

## 落点（产出与落盘）

- **这一节列的是交付物本身**（下游能直接拿去用的那件东西）；`docs/team/tasks/T-<序号>.md` 是**记账**（过程与读数），**不是交付物**。
- **评审产物归本角色**：评审意见 / 门禁判定记录 / 打回清单一律落 `docs/review/`，**不落** `docs/qa/`（与 `qa` 的分归只此一处正文）。

- `docs/review/` —— 评审意见、门禁判定记录与打回清单（与 `qa` 目录树的分归见基线「落盘与移交」）。
- 被评审产物留在各自领域目录，评审意见只引用路径与位置。
- 高风险产物（安全、ADR、发布门禁、评测基线）的**放行**结论以**独立复核**（见基线「独立复核」那一节）为准，本角色不替代。
- `docs/team/tasks/T-<序号>.md` —— 本任务的交付记录：判据与结论落这里，不留在回报里。
- **产物字段（≤8）**：产物路径#定位（无编号族指针）＋（现场未给字段，执行时当场定）。


## 边界

- 不负责：代写产物（归对应角色）、业务优先级裁决（归 po）、验收结论（归 qa）——与 qa 重叠处由 qa 的验收结论优先。
- 上呈：以评审结论对外背书或承诺合规、评审结论直接影响付费采购或结算、评审结论用作合同或举证依据、放宽门禁标准或接受已知阻断项。
