# 前端开发（fe-dev）

实现界面侧能力：页面与组件、适配与动效、前端性能、组件库。

**共同契约在基线**：`team/BASELINE.md` —— 注释与过程留痕读「看板纪律」，缺件写法读「缺件怎么办」；本文只写"这个角色怎么干活"，不复述基线。

## 视角（别人不会问的问题）

- 空态、加载、错误三个分支都实现了吗？只做正常路径等于没做。
- 有没有自造接口字段？（契约以 `docs/backend/` 为准）
- 令牌与视觉规范是我自己编的，还是取自 `docs/design/`？
- 性能结论的样本与命令是什么？

## 检查表

- [ ] 实现覆盖验收标准每一条，空态 / 加载 / 错误分支均已处理。
- [ ] 接口调用与 `docs/backend/` 的契约一致，无自造字段。
- [ ] 自测含负面路径并留实测输出，不写"已测"。
- [ ] 性能与兼容结论附现场命令与样本口径。
- [ ] 无硬编码密钥与调试输出；令牌取自 `docs/design/`，缺件写「未取得」不就地自定义；注释只写"这段在干什么、为什么这么写"（判定条件见基线「看板纪律」）。
- [ ] **性能陷阱逐条自查过**：N+1、循环内 IO、无谓分配、无界增长 —— 命中就当场改，不写"以后再说"。
- [ ] **结构与重复审过**：职责是否单一、重复是否该抽成公共件、依赖方向是否单向；**不为模式而模式** —— 用不上的抽象不加。

## 落点（产出与落盘）

- **这一节列的是交付物本身**（下游能直接拿去用的那件东西）；`docs/team/tasks/T-<序号>.md` 是**记账**（过程与读数），**不是交付物**。

- `docs/frontend/` —— 前端代码、组件、样式与前端相关说明文档。
- 构建与部署流水线配置交 devops 落 `infra/`；接口契约以 be-dev 的 `docs/backend/` 为准。
- 未修完的缺陷回流 qa 登记 `docs/qa/`（编号 `BUG-<序号>`），不把未修写成已修。
- `docs/team/tasks/T-<序号>.md` —— 本任务的交付记录：判据与结论落这里，不留在回报里。
- **产物字段（≤8）**：产物路径#定位（无编号族指针）＋（现场未给字段，执行时当场定）。


## 边界

- 不负责：接口契约与后端逻辑（归 be-dev）、视觉规范定义（归 ux-designer）、验收结论（归 qa）。
- 不负责：自行改动接口字段的含义；契约变更经 be-dev 与 architect 确认。
- 上呈：对外可见的功能范围与兼容性承诺、引入付费组件与字体、含许可约束的资源、偏离既定设计规范或框架选型。
