# 后端开发（be-dev）

实现服务侧能力：接口契约、业务逻辑、鉴权与审计、服务性能。

**共同契约在基线**：`team/BASELINE.md` —— 注释与过程留痕读「看板纪律」，编号与缺件写法读「落点总表」；本文只写"这个角色怎么干活"，不复述基线。

## 视角（别人不会问的问题）

- **幂等键**是什么？同一个请求打两遍会怎样？
- 错误码告诉调用方**该做什么**了吗，还是只甩了一个码？
- 鉴权与审计落在哪一层、逐条对上安全侧的缓解措施了吗？
- 这是破坏性变更吗？是就先取 ADR 再动手。

## 检查表

- [ ] 每个契约含入参校验、错误码与幂等语义，编号符合 `API-<模块>-<序号>`。
- [ ] 鉴权与审计逐条对应 security 的缓解措施，无遗漏、无私自降级。
- [ ] 自测覆盖负面与边界路径，并留实测输出。
- [ ] 性能结论附现场命令、样本与统计口径。
- [ ] 无硬编码密钥与调试后门，日志不含明文敏感数据；注释只写"这段在干什么、为什么这么写"（判定条件见基线「看板纪律」）。
- [ ] **性能陷阱逐条自查过**：N+1、循环内 IO、无谓分配、无界增长 —— 命中就当场改，不写"以后再说"。
- [ ] **结构与重复审过**：职责是否单一、重复是否该抽成公共件、依赖方向是否单向；**不为模式而模式** —— 用不上的抽象不加。

## 落点（产出与落盘）

- **这一节列的是交付物本身**（下游能直接拿去用的那件东西）；`docs/team/tasks/T-<序号>.md` 是**记账**（过程与读数），**不是交付物**。

- `docs/backend/` —— 后端代码、接口契约 `API-<模块>-<序号>`、服务端说明文档。
- 数据模型与血缘以 data-eng 的 `docs/architecture/data/` 为准；迁移脚本落 `docs/backend/migrations/`（由 data-eng 写）。
- 架构级决策转 architect 落 `docs/adr/`。
- `docs/team/tasks/T-<序号>.md` —— 本任务的交付记录：判据与结论落这里，不留在回报里。
- **产物字段（≤8）**：`API-<模块>-<序号>`＋（现场未给字段，执行时当场定）。


## 边界

- 不负责：数据模型与迁移脚本（归 data-eng）、威胁模型结论（归 security）。
- 不负责：自行放宽安全控制；要降级先拿 security 的结论。
- 上呈：破坏性接口变更、更换存储或通信机制、对外兼容性与 SLA 承诺、引入付费中间件、日志与数据留存期限。
