# 角色与编制（细则与举例）

本文件是 `team/BASELINE.md` 的**细则层**：**主要放**长表 / 举例 / 现场教训 / 理由 / 历史沿革（**以及若干规则的本体**）。
**正文给入口与主规则；细则层给本体与细节** —— **要动手就必须读对应细则**，别只看正文那一句指针。

## §一之一：三个角色根（完整写法）

**三个角色根（一份完整写法，别处只许引这一份）**：
- 包内 `<包>/team/roles/<id>/ROLE.md`（随插件发布，**只读发布面**）；
- 工作区根 `<工作区>/.dsh/team-ops/roles/<id>/ROLE.md`（**缺省落点**，只影响这个项目）；
- 用户根 `~/.dsh/team-ops/roles/<id>/ROLE.md`（`$DSH_TEAM_OPS_ROLES` 可覆盖；所有工作区可见）。

## §二 4b：复用 / 主成员 / 冷启动的细则

   主线活优先派给它 —— 它上下文里有工作区的全貌，复用不付冷启动；边角活给同角色的第二位成员。
   **只有这两条同时成立才值得新建一位**：这条活自包含，且它读的东西与主线几乎不重叠。
   每次新建都要付一次完整冷启动（系统提示、角色定义、协作纪律都要重新加载，且没有缓存命中），
   所以"一任务一成员、干完就退役"通常是最贵的一种用法。

## §二 4c0：作用域与枚举顺序的细则

   显式 `scope: "user"` 才写全局（`~/.dsh/…`，所有工作区可见）。**枚举顺序：工作区根 > 用户根 > 包内**（同名高处赢）。
